# 创意工坊

这里放个人工具项目和待验证的想法。现有的 [DoneLog](./DoneLog/README.md) 已接入本目录；`DoneLog/` 是指向原仓库的目录连接，代码仍保存在 `D:\code\uni-app\DoneLog`，原有 Git 历史和构建环境可继续使用。[每日资讯](./DailyInfo/README.md)和[美食地图](./FoodMap/README.md)是只含规划文档的新子项目。

各项目的当前状态见 [项目进度](./PROJECTS.md)。

项目协作规则见 [AGENTS.md](./AGENTS.md)。每次子项目完成变更时，更新 [项目进度](./PROJECTS.md) 中的描述和最近变更。

## 项目方向

| 想法 | 建议归属 | 第一版可验证的结果 |
| --- | --- | --- |
| 根据工作表生成闹钟，支持手动修改和调班 | [DoneLog 待做功能](./DoneLog/TODO.md) | 导入一份班表，预览日期和提醒时间，确认后生成本地提醒；修改或调班后同步更新提醒，过期提醒自动取消 |
| 每日新闻按兴趣过滤并发邮件 | [每日资讯](./DailyInfo/README.md) | 从明确的新闻源获取内容，按关键词或主题过滤，每天发送一封摘要邮件并避免重复 |
| 演唱会开抢、海航 666 放票提醒 | [每日资讯待做功能](./DailyInfo/TODO.md) | 对指定官方来源检测开售时间或状态变化，有新信息时发送邮件并附原始链接 |
| 网页或截图中的店铺整理、附近美食、沿途找店 | [美食地图](./FoodMap/README.md) | 提取并核对店铺，保存后按当前位置或路线筛选 |

## 实施顺序

1. 先做 DoneLog 班表提醒：现有 App 已有本地事件提醒和 Android 定时通知能力，可复用；导入、调班和过期清理是新增部分。
2. 再做每日资讯摘要：先限定少量可信来源和清晰的过滤规则，验证摘要质量与邮件送达。
3. 最后做开抢、放票监测：这类信息依赖各平台实际提供的页面或接口，先确认可稳定获取的官方来源，再定义检查频率和通知时效。

美食地图先收集代表性网页或截图，再确定首版平台与开发顺序。

## 开始开发前需要确认

- 班表样例：文件格式、日期与班次列、一个班次对应的提醒时间，以及调班如何标注。
- “过期了就删除”是只删除闹钟，还是连历史班表记录一起删除。
- 海航 666 指哪一种产品或页面；演唱会信息以哪个官方售票平台为准。
- 资讯邮件的收件地址与期望发送时间。
- 美食地图的代表性网页或截图、附近范围，以及沿途“一公里”的距离定义。
